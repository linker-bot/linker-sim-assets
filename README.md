# linker-robot-assets

The shared robot-asset bundle for `linker-sim` and downstream consumers.

This package ships:

- the asset tree at [`src/linker_robot_assets/assets/`](src/linker_robot_assets/assets/) — URDF / MJCF + meshes, organised by `components/`, `units/`, and `workstations/` (binaries are stored via git LFS);
- the **composer** that builds workstation URDFs from components ([`composer/`](src/linker_robot_assets/composer/));
- two validators ([`validate_workstation.py`](src/linker_robot_assets/validate_workstation.py), [`validate_component_mjcf.py`](src/linker_robot_assets/validate_component_mjcf.py));
- a thin **loader API** at the package root: `asset_root()`, `workstations()`, `units()`, `load_manifest(name)`.

## Asset layout

| dir | what | consumed by |
|---|---|---|
| `components/{arms,hands,bases}/` | **parametric templates** — `{V}`/`{S}` placeholders, both variants, no manifest; *not directly loadable*. The composer's inputs. | composer only |
| `units/` | **atomic single-system units** — one articulation each, `freeze_base` on its own root: solo arm / arm+hand / solo hand. | Isaac Sim (per-robot articulations), real-robot teleop |
| `workstations/` | **full multi-robot scenes** — torso/bench + 2 arms + 2 hands, one composed model. | linker-sim (MuJoCo), viser |

Both `units/` and `workstations/` hold composed, loadable `workstation.urdf` + `workstation.xml` (MJCF) + `manifest.yaml`.

**Unit naming** = component short-tokens + side (`l`/`r`). Arm token = component dir name (`ar5_08`); hand token = component name minus `linkerhand_` (`l6`):

| kind | grammar | example |
|---|---|---|
| solo arm | `<arm>_<side>` | `ar5_08_l` |
| arm+hand | `<arm>_<hand>_<side>` | `ar5_08_l6_l` |
| solo hand | `<hand>_<side>` | `l6_l` |

**Solo units are auto-derived.** A component with `emit_solo_unit: true` in its `meta.yaml` gets a loadable solo unit per variant, generated by
`python -m linker_robot_assets.composer.derive_solo` (which writes a *generated* `recipe.yaml` and composes it). Arm+hand and other multi-component units keep hand-authored recipes.

## Install profiles

| Profile | What you get | Pulls |
|---|---|---|
| `pip install linker-robot-assets` | Loader API + bundled assets. | `pyyaml` |
| `pip install linker-robot-assets[authoring]` | Plus composer + validators. | `mujoco`, `numpy` |

The runtime profile is intentionally light so consumers (e.g. `linker-sim`'s registry) only pay for `pyyaml`. Authoring tools are gated behind `[authoring]`.

## Usage

```python
from linker_robot_assets import asset_root, workstations, units, load_manifest

asset_root()                  # PosixPath('.../linker_robot_assets/assets')
workstations()                # ['a7_lite_l6_dc', 'ar5_l6_bench_bimanual', ...]
units()                       # ['ar5_08_l', 'ar5_08_l6_l', 'l6_l', ...]
load_manifest('a7_lite_l6_dc')          # full-scene manifest
load_manifest('ar5_08_l', subdir='units')  # atomic-unit manifest
```

CLI (with `[authoring]`):

```bash
python -m linker_robot_assets.composer.compose <workstation_dir> [--check-drift]
python -m linker_robot_assets.composer.derive_solo [--check-drift]
python -m linker_robot_assets.validate_workstation <workstation_dir>
python -m linker_robot_assets.validate_component_mjcf <component_dir> [--variant NAME]
```
